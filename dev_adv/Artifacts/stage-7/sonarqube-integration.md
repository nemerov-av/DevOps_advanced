# Интеграция микросервисов на Golang с SonarQube

Данная инструкция описывает процесс подключения нового микросервиса на Golang к нашей системе статического анализа кода SonarQube. Интеграция внедряется в GitLab CI и блокирует отправку релизов, если код не проходит настроенный Quality Gate.

## Пошаговая инструкция

### Шаг 1. Создание проекта в SonarQube
1. Авторизуйтесь в веб-интерфейсе SonarQube (`https://sonarqube.<вашдомен>`).
2. В правом верхнем углу нажмите **Create Project** -> **From GitLab** (или **Manually**, если прямой интеграции с репозиторием нет).
3. Введите **Project display name** (например, `my-golang-service`) и **Project key** (идентификатор проекта, запомните его, он понадобится в CI).
4. Укажите основную ветку репозитория (`master` или `main`).

### Шаг 2. Генерация токена доступа
1. В настройках созданного проекта (или в профиле пользователя) перейдите в раздел **Security**.
2. Сгенерируйте новый токен (тип `Project Token`).
3. Скопируйте полученный токен (он показывается только один раз!).

### Шаг 3. Настройка переменных в GitLab CI/CD
1. Перейдите в ваш репозиторий GitLab: **Settings** -> **CI/CD** -> **Variables**.
2. Добавьте две новые переменные:
   * `SONAR_HOST_URL`: `https://sonarqube.<вашдомен>`
   * `SONAR_TOKEN`: вставьте токен, скопированный на предыдущем шаге (обязательно отметьте флаг **Masked**, чтобы токен не попадал в логи).

### Шаг 4. Настройка тестирования Golang (опционально, но рекомендуется)
SonarQube отлично анализирует Go, но для отображения покрытия тестами (Code Coverage) ему нужен готовый отчет.
Добавьте в корень вашего проекта файл `sonar-project.properties` (или передавайте эти параметры флагами в CI):
```properties
sonar.projectKey=my-golang-service
sonar.sources=.
sonar.go.coverage.reportPaths=coverage.out
sonar.exclusions=**/*_test.go,**/vendor/**
